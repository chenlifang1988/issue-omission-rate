# 问题遗漏率统计工具

一个用于统计问题遗漏率的轻量 Web 工具。分别导入「客户端问题表」与「测试验证问题表」，借助关键词规则自动对问题描述分类，人工校对后比对两个来源的问题类型集合，计算问题遗漏率，并支持按项目分别统计。

## 使用流程

1. 在「问题类型字典」中维护标准问题类型，并为每个类型配置关键词规则（首次启动会自动写入默认分类与关键词规则）。
2. 在「批量导入」页的两个上传区分别导入客户端问题表与测试验证问题表，必须映射「问题描述」列；若表中已带分类列，可再映射「分类列」；如需按项目统计，请把两张表的项目列都映射到「项目」。
3. 工具优先按「分类列」归类；无分类列时按关键词规则对描述自动分类；未命中的问题进入「待分类」。
4. 在「分类校对」页查看明细，对待分类或分错的问题人工指定类型；类型输入框提供已有分类候选，若下拉中没有匹配分类，可直接输入新名称，后台会自动创建该分类并归类；可按项目筛选。人工分类后会弹出「学习分类规则」对话框，勾选/补充要记住的关键词，点「记住规则」即写入该类型的关键词规则，并自动归类其他能被新规则命中的待分类问题。
5. 在「统计看板」查看总体与分项目的遗漏率；点击「客户端未测出问题类型数 B」卡片可展开未测出类型明细，并直接填写每个类型的问题原因定位与改进措施，失焦即保存。

## 指标口径

```
T = 来源为「测试验证」且已分类的问题类型集合
C = 来源为「客户端」且已分类的问题类型集合
A = |T|           测试验证问题类型数
B = |C \ T|       客户端未测出问题类型数（仅客户端出现过、测试验证未出现过的类型）
客户端问题类型数 = 客户端原始「问题分类」列的去重值个数（反映原始数据，不参与遗漏率计算）
遗漏率 = B / (A + B)
```

- 按问题类型去重统计，同一类型出现多次只计一次。
- 同一类型既在测试验证出现又在客户端出现（重叠类型），视为未遗漏，只计入分母 A，不计入分子 B。
- 「待分类」记录不参与统计，看板会单独提示其数量。
- 看板同时展示 A、客户端问题类型数 C、B、重叠类型数、遗漏率与待分类记录数；其中 C 直接取客户端原始「问题分类」列的去重个数，不考虑与测试验证的重叠。

示例：测试验证类型 = {电子与通讯, 流体与液路, 光学与成像, 温控}，客户端类型 = {电子与通讯, 流体与液路, 结构与装配, 软件与逻辑}，则 A = 4、B = 2、重叠 = 2，若客户端原始「问题分类」列有 4 个不同取值则 C = 4，遗漏率 = 2 / (4 + 2) = 33.3%。仓库 `samples/` 提供了可直接导入的两张示例表。

## 默认分类字典

首次启动时，若字典为空，服务会自动写入 38 个「领域 × 问题性质」分类及其关键词规则，可在「问题类型字典」中继续增删改。每个分类的关键词由两部分组成：面向描述的领域关键词，以及该分类覆盖的原始细分分类名（别名），别名保证「分类列」导入时可精确映射。

| 领域 | 分类 |
|------|------|
| 软件 | 软件功能缺陷、软件逻辑/脚本异常、参数/配置异常、数据流转异常 |
| 算法/生信 | 算法缺陷、测序质量异常、生信分析异常、生化信号异常 |
| 光学/成像 | 成像质量异常、对焦异常、显示/屏幕异常、激光/光源异常、图像采集异常 |
| 温控 | 温控异常 |
| 流体/液路 | 流体/过液异常、气泡异常、管路/压力异常、泵阀异常、储液/泄漏异常、清洗异常 |
| 运动/机构 | 运动控制异常、机构到位/门锁异常、make load 产出异常、make load 机构精度异常 |
| 电子/通讯 | 供电/上电异常、控制/板卡异常、EMC/电磁兼容、SBC异常、通讯/网络/连接异常、RFID识别异常 |
| 结构/装配 | 结构干涉/磨损异常、设计缺陷 |
| 其他 | 来料问题、芯片工艺异常、试剂异常、线材/走线异常、环境/测试条件异常、人为操作/搬运问题 |

分类定义见 `backend/src/services/dictionary.js`。


## 自动分类规则

- 若导入时映射了「分类列」且该列有值，优先用「分类列」的值归类；该值会经同一套关键词规则映射到标准类型。
- 否则按「问题描述」自动分类；映射了「分类列」但未命中时，同样回退到描述分类。
- 为问题类型配置关键词；分类时忽略描述与关键词的大小写、空白与常见标点差异后做包含匹配。
- 多个关键词命中时，选择匹配关键词最长的类型。
- 问题类型名称本身作为隐式关键词参与匹配。
- 未启用的问题类型不参与自动分类。

## 技术栈

- 前端：Vue 3 + Vite + TypeScript + ECharts + Vue Router
- 后端：Node.js + Express + better-sqlite3
- 数据库：SQLite（默认 `backend/data/omission.db`）

## 目录结构

```
.
├── backend/                 Express API 与 SQLite
│   ├── src/

│   │   ├── services/        关键词分类、导入解析、遗漏率计算、默认分类字典、分项目统计、主动学习

│   │   └── server.js        启动入口

│   └── test/                单元测试
```

## 快速开始

```bash
# 安装全部依赖
npm run install:all

# 同时启动后端与前端（后端 3001，前端 5173）
npm run dev
```

浏览器访问 http://localhost:5173 。前端通过 Vite 代理将 `/api` 请求转发到后端 `http://localhost:3001`。

## 多项目统计

- 项目维度复用每条记录的「项目」字段（数据库中为 `module` 列）。导入时把两张表的项目名称映射到「项目」列即可。
- 两个来源的项目名需保持一致（工具会比较去除首尾空格后的值；大小写与写法差异需在源表统一）。未映射或空值的记录归入「未标注项目」。
- 导入的覆盖模式为「清空该来源中相同项目的数据」，因此导入项目 B 不会影响项目 A；同一项目重复导入会先清除该项目旧数据。
- 看板提供「分项目统计」表，逐项目列出 A、B、重叠、遗漏率、客户端问题类型数 C 与待分类数；点击某行即按该项目下钻到上方的卡片与仪表盘，点击首行「全部项目」恢复全局视图。
- 点击「分项目统计」中某项目的「重命名」可修改项目名称，改动会同步到该项目的所有记录（含两个来源）；若新名称与已有项目相同则合并为一个项目；「未标注项目」也可重命名，用来给未映射项目的记录补标名称。

## 导入说明

- 支持 `.xlsx` / `.xls` / `.csv`，单文件不超过 10MB。
- 必须映射「问题描述」列，可选映射「分类列」、「项目」与「发生日期」列。
- 每个来源可选择「导入前清空该来源中相同项目的数据」（默认）或「追加导入」。
- 问题类型需先存在于字典中；未命中规则的行会进入「待分类」，不会丢失。

## 字典初始化

字典为空时服务会自动写入默认分类。如需手动重建字典（会清空现有字典与问题数据）：

```bash
cd backend
node scripts/init-dictionary.js --reset
```
