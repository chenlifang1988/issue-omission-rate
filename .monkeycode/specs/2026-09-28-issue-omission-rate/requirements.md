# Requirements Document

## Introduction

问题遗漏率统计工具是一个 Web 网页应用，用于将「客户端问题」与「测试验证问题」两张问题表分别导入，借助关键词规则自动对问题按描述进行分类，经人工校对后比对两个来源的问题类型集合，计算问题遗漏率。

核心流程：

1. 在「问题类型字典」中维护标准问题类型，并为每个类型配置关键词规则。
2. 在「批量导入」页分别导入客户端问题表与测试验证问题表，映射「问题描述」列。
3. 工具按关键词规则对每条问题描述自动分类；未命中的问题进入「待分类」。
4. 在「分类校对」页查看明细，对待分类或分类错误的问题人工指定类型。
5. 工具比对两个来源已分类的问题类型集合，计算遗漏率。

核心指标口径：

```
T = 来源为「测试验证」且已分类的问题类型集合
C = 来源为「客户端」且已分类的问题类型集合
A = |T|                    （测试验证问题类型数）
B = |C \ T|                （客户端未测出问题类型数：仅客户端出现过、测试验证未出现过的类型）
客户端问题类型数 = 客户端原始「问题分类」列的去重值数（反映原始数据，不参与遗漏率计算）
遗漏率 = B / (A + B)
```

说明：

- 计数按问题类型去重，同一类型出现多次只计一次。
- 同一类型既在测试验证出现又在客户端出现（重叠类型），视为未遗漏，只计入分母 A，不计入分子 B。
- 仍处于「待分类」的问题不参与统计，并在看板上提示其数量。

## Glossary

- **统计工具 (Tool)**: 本文档描述的问题遗漏率统计 Web 应用。
- **问题记录 (Issue Record)**: 从表格导入的一条问题明细，包含原始描述、来源、分类结果等。
- **来源 (Source)**: 问题记录所属表格，取值仅限「测试验证」或「客户端」。
- **问题描述 (Description)**: 问题记录中用于分类的原始文本。
- **问题类型 (Issue Type)**: 标准问题分类项，由统计人员维护。
- **问题类型字典 (Issue Type Dictionary)**: 全部标准问题类型及其关键词规则的集合。
- **关键词规则 (Keyword Rule)**: 归属于某个问题类型的关键词，用于按描述自动分类。
- **自动分类 (Auto Classification)**: 按关键词规则为问题描述匹配问题类型的过程。
- **待分类 (Pending)**: 未命中任何关键词规则、尚未指定问题类型的问题记录。
- **人工校对 (Manual Review)**: 由统计人员为问题记录指定或修正问题类型。
- **测试验证集合 (T)**: 已分类且来源为「测试验证」的问题类型集合。
- **客户端集合 (C)**: 已分类且来源为「客户端」的问题类型集合。
- **重叠类型 (Overlap Type)**: 同属 T 与 C 的问题类型，即 `T ∩ C`，视为未遗漏。
- **客户端未测出问题类型 (Missed Issue Type)**: 属于 C 且不属于 T 的问题类型，即 `C \ T`。
- **测试验证问题类型数 (A)**: `|T|`，包含重叠类型。
- **客户端问题类型数 (C)**: 客户端来源原始「问题分类」列的去重值个数，直接反映原始数据，不参与遗漏率计算。
- **未测出问题类型数 (B)**: `|C \ T|`。
- **遗漏率 (Omission Rate)**: 按 `B / (A + B)` 计算的比例，以百分比展示。
- **项目 (Project)**: 问题归属的项目，用于区分与筛选数据；未映射或为空的记录归入「未标注项目」。
- **统计人员 (Analyst)**: 使用本工具维护字典与规则、导入数据、校对分类、查看统计结果的人员。

## Requirements

### Requirement 1

**User Story:** AS 统计人员，I want 维护问题类型字典及每个类型的关键词规则，so that 自动分类有统一的标准和依据。

#### Acceptance Criteria

1. The Tool SHALL 提供问题类型的查询、新增、重命名、启用/停用与删除能力。
2. The Tool SHALL 提供为指定问题类型新增、删除关键词规则的能力。
3. WHEN 统计人员提交新增问题类型，the Tool SHALL 校验名称非空且不重复。
4. WHEN 统计人员新增关键词规则，the Tool SHALL 校验关键词非空且在同类型下不重复。
5. IF 统计人员删除一个已被问题记录引用的类型，the Tool SHALL 拒绝删除并提示引用数量。
6. WHILE 问题类型被停用，the Tool SHALL 在自动分类与人工选择候选中排除该类型。

### Requirement 2

**User Story:** AS 统计人员，I want 独立导入客户端问题表和测试验证问题表，so that 两个来源的数据可以分别管理。

#### Acceptance Criteria

1. The Tool SHALL 提供两个独立的上传入口，分别对应「客户端」与「测试验证」来源。
2. WHEN 统计人员上传 `.xlsx`、`.xls` 或 `.csv` 文件，the Tool SHALL 解析并返回可选列与数据预览行数。
3. The Tool SHALL 要求统计人员将某一列映射为「问题描述」，并允许可选映射「分类列」「项目」与「发生日期」列。
4. WHEN 统计人员确认导入，the Tool SHALL 仅导入校验通过的行，并记录其来源与导入批次。
5. The Tool SHALL 提供「导入前清空该来源中相同项目的数据」选项，且默认勾选。
6. WHEN 统计人员对同一来源选择清空后导入，the Tool SHALL 移除该来源中与本次导入项目相同的已有记录后再写入新数据，其他项目不受影响。
7. The Tool SHALL 在导入完成后展示成功行数、失败行数、自动分类行数与待分类行数。
8. WHEN 字典为空，the Tool SHALL 在启动时写入默认的「领域 × 问题性质」分类及其关键词规则。

### Requirement 3

**User Story:** AS 统计人员，I want 工具按关键词规则对问题描述自动分类，so that 无需逐条手工归类即可完成大部分分类。

#### Acceptance Criteria

1. WHEN 一行问题记录被导入，the Tool SHALL 依据已启用的问题类型及其关键词规则对问题描述执行匹配。
2. The Tool SHALL 忽略描述与关键词的大小写、空白与常见标点差异后再匹配。
3. WHEN 多个关键词命中同一描述，the Tool SHALL 选择匹配关键词最长的类型作为分类结果。
4. WHEN 至少一个关键词命中，the Tool SHALL 将问题记录的分类状态标记为「自动」并记录命中的关键词。
5. IF 没有任何关键词命中，the Tool SHALL 将问题记录的分类状态标记为「待分类」且不指定问题类型。
6. The Tool SHALL 将问题类型名称本身视为该类型的隐式关键词参与匹配。
7. WHEN 导入行映射了「分类列」且该列非空，the Tool SHALL 优先将「分类列」的值按关键词规则映射到问题类型。
8. IF 「分类列」的值未能映射到任何问题类型，the Tool SHALL 回退到按「问题描述」分类。

### Requirement 4

**User Story:** AS 统计人员，I want 查看导入明细并人工校对分类结果，so that 可以修正自动分类的错误或补全待分类问题。

#### Acceptance Criteria

1. The Tool SHALL 以列表形式展示问题记录明细，包含来源、原始描述、问题类型与分类状态。
2. The Tool SHALL 支持按来源、问题类型、分类状态、项目与时间范围筛选明细。
3. WHEN 统计人员为一条问题记录指定或修改问题类型，the Tool SHALL 将该记录分类状态标记为「人工」。
4. The Tool SHALL 在列表中对待分类记录予以醒目提示。
5. The Tool SHALL 展示当前待分类记录数量。
6. The Tool SHALL 允许删除单条问题记录。
7. The Tool SHALL 在人工指定类型时提供已有类型的候选下拉，并允许自由输入类型名称。
8. WHEN 统计人员输入的问题类型名称不存在，the Tool SHALL 创建该问题类型、将其记录到字典，并把该记录归类到新类型。

### Requirement 5

**User Story:** AS 统计人员，I want 工具按分类结果自动计算遗漏率，so that 无需手工汇总即可得到准确指标。

#### Acceptance Criteria

1. The Tool SHALL 仅使用已分类（分类状态为「自动」或「人工」）的问题记录参与统计。
2. The Tool SHALL 计算 T 为来源「测试验证」已分类的问题类型集合，并计算 A 为 T 的规模。
3. The Tool SHALL 计算 C 为来源「客户端」已分类的问题类型集合，并计算 B 为 `C \ T` 的规模。
4. WHILE 某个问题类型同属 T 与 C，the Tool SHALL 将该类型计入 A 且不计入 B。
5. The Tool SHALL 计算遗漏率为 `B / (A + B)`，并以百分比形式展示。
6. IF `A + B` 等于 0，the Tool SHALL 将遗漏率展示为 0% 并提示当前无有效数据。
7. The Tool SHALL 同时展示 A、B、客户端问题类型数 C、重叠类型数、遗漏率与待分类记录数。
8. WHEN 统计人员点击「客户端未测出问题类型数 B」，the Tool SHALL 展示 B 的明细，包含问题类型名称、客户端记录数、示例问题描述、问题原因定位与改进措施。
9. The Tool SHALL 使 B 的明细遵循当前统计筛选条件。
10. The Tool SHALL 允许统计人员在 B 明细中直接填写或修改每个问题类型的「问题原因定位」与「改进措施」并保存，保存后重新打开时能回显。
11. The Tool SHALL 按问题类型保存「问题原因定位」与「改进措施」，同一类型在不同筛选条件下回显一致的内容。

### Requirement 6

**User Story:** AS 统计人员，I want 按时间范围和项目筛选查看统计结果，so that 可以关注特定周期或特定项目的遗漏情况。

#### Acceptance Criteria

1. WHEN 统计人员指定时间范围，the Tool SHALL 仅使用发生日期落在该范围内的记录参与统计。
2. WHEN 统计人员指定项目，the Tool SHALL 仅使用该项目的记录参与统计。
3. WHEN 统计人员同时指定时间范围与项目，the Tool SHALL 按两个条件的交集进行统计。
4. The Tool SHALL 以数值卡片与图表两种形式展示统计结果。
5. WHEN 统计条件变化，the Tool SHALL 同步刷新数值与图表。

### Requirement 7

**User Story:** AS 统计人员，I want 数据持久化在后端数据库，so that 服务重启或多人访问后数据不丢失。

#### Acceptance Criteria

1. The Tool SHALL 将问题类型、关键词规则与问题记录持久化到后端数据库。
2. WHEN 后端服务重启，the Tool SHALL 保留已持久化的数据。
3. The Tool SHALL 通过前端统一 API 前缀访问后端接口。

### Requirement 8

**User Story:** AS 统计人员，I want 按项目分别统计遗漏率并在看板对比，so that 可以区分不同项目的数据并定位问题集中的项目。

#### Acceptance Criteria

1. The Tool SHALL 支持在导入时将某一列映射为「项目」，并把项目值随问题记录一并持久化。
2. The Tool SHALL 将未映射项目或项目值为空的记录归入「未标注项目」。
3. WHEN 统计人员对同一来源以覆盖模式导入某项目的数据，the Tool SHALL 仅清除该来源中相同项目（含未标注项目）的旧记录，保留其他项目。
4. The Tool SHALL 在看板提供分项目统计，逐项目展示 A、B、重叠类型数、遗漏率、客户端问题类型数 C 与待分类记录数。
5. WHEN 统计人员点击某个项目，the Tool SHALL 按该项目过滤看板卡片与图表；点击「全部项目」时恢复全局视图。
6. WHILE 统计人员切换时间范围，the Tool SHALL 使分项目统计与整体统计保持同一时间口径。
7. The Tool SHALL 允许统计人员在分项目统计中重命名某个项目，改动 SHALL 同步更新该项目下所有问题记录（两个来源）。
8. WHEN 统计人员将某项目重命名为一个已存在的项目名，the Tool SHALL 将两者合并为同一项目。
9. IF 统计人员将项目名清空或命名为「未标注项目」，the Tool SHALL 拒绝保存并提示。
10. The Tool SHALL 允许对「未标注项目」重命名，以给未映射项目的记录补标名称。

### Requirement 9

**User Story:** AS 统计人员，I want 在人工分类后把分类逻辑沉淀为关键词规则，so that 后续导入的相似问题可以被自动分类，减少重复人工工作量。

#### Acceptance Criteria

1. WHEN 统计人员将一个待分类或分类错误的问题人工指定为某问题类型，the Tool SHALL 从该问题描述中提取候选关键词。
2. The Tool SHALL 排除候选关键词中已属于该类型的规则、与类型名相同、以及「问题」「异常」「故障」等无区分度的泛化词。
3. WHEN 提取到候选关键词，the Tool SHALL 向统计人员展示确认框，允许勾选候选关键词并补充自定义关键词。
4. WHEN 统计人员确认，the Tool SHALL 将勾选与补充的关键词写入该问题类型的关键词规则。
5. WHEN 新规则写入后，the Tool SHALL 使用更新后的规则重新分类当前处于「待分类」的问题记录，并给出自动归类数量。
6. WHEN 统计人员选择忽略，the Tool SHALL 不写入任何规则且不影响已完成的分类结果。
7. The Tool SHALL 在未提取到候选关键词时不弹出确认框。
